HSWare Studio v14.1.1 - Security & Reliability Hardening
========================================================

Release focus
-------------
This release hardens the v14.1.x application without changing the six-source logo-selection workflow.

Security fixes
--------------
1. Remote fetch DNS pinning
   - Remote hostnames are resolved and validated against private/reserved IP ranges.
   - The actual TCP/TLS connection is made to the validated public IP, preventing a second DNS lookup from redirecting the connection to an internal address.
   - HTTPS keeps the original hostname for TLS SNI and Host validation.
   - Redirect destinations continue to be independently validated.

2. SVG logo hardening
   - SVGs returned through logo preview/file proxy routes are validated before being served.
   - Active content such as scripts, foreignObject, iframe/object/embed, inline event handlers, JavaScript/VBScript URLs, HTML data URLs, unsafe styles, external href references, external CSS URL references, DOCTYPE and ENTITY declarations is rejected.
   - Accepted SVG responses receive a restrictive sandbox Content-Security-Policy in addition to nosniff.

3. Streaming request-size enforcement
   - API request limits no longer depend only on Content-Length.
   - Request streams are counted byte-by-byte and aborted once their endpoint class limit is exceeded.
   - Current limits remain: normal API payloads 1 MB, images 2 MB, backup restore/octet-stream 100 MB.

Reliability fixes
-----------------
4. Safer destructive reset
   - Admin reset now creates a safety backup before deletion begins.
   - Reset database mutations run inside one transaction.
   - Any reset failure triggers rollback.
   - Reset activity records include the safety backup ID and filename.

Compatibility
-------------
- Six independent logo sources are preserved:
  Logo.dev Verified Product, ln-dev7/logos-apps, Official Website,
  WinGet Manifest Icons, Homarr Dashboard Icons, selfh.st Icons.
- Existing authentication, CSRF, role checks, backup/restore format and catalog workflow are preserved.

Validation target
-----------------
Before production deployment, run on the deployment host:
  npm ci
  npm run typecheck
  npm run check
  npm run build

Then smoke-test login, Partner/Admin permissions, all six logo sources, backup/restore, catalog/import/update workers and reset on a disposable MySQL database.
